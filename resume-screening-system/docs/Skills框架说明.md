## 什么是 Skills？

**Skills（技能/能力模块）** 是一套封装好的、可复用的 AI 能力定义，它决定了 AI 在特定任务上：

- **能做什么** - 具备哪些评估能力
- **按什么标准做** - 遵循什么规则和逻辑
- **做到什么程度** - 输出质量和一致性
- **如何验证结果** - 确保结果可审计、可追溯

### 通俗理解

如果把 AI 系统比作一个员工：

| 概念 | 类比 | 说明 |
|------|------|------|
| **Skills** | 员工的岗位能力 | 这个员工"会什么"，具备哪些专业技能 |
| **Prompts** | 具体的工作指令 | 告诉员工"现在去做什么"，执行某个具体任务 |

一个优秀的招聘 HR，其 Skills 包括：
- 简历筛选能力（理解岗位需求、识别候选人优势）
- 评估判断能力（打分、分档、给出建议）
- 信息核实能力（搜索验证、识别风险）
- 沟通表达能力（输出清晰的评估报告）

这些 Skills 是员工多年培训和经验积累的结果，不是一句话指令就能获得的。

## Skills 与 Prompts 的区别

这是理解本系统的关键概念。

### 核心区别

| 维度 | Skills（技能/能力模块） | Prompts（提示词/指令） |
|------|------------------------|----------------------|
| **本质** | 封装好的能力定义 | 单次执行的指令 |
| **类比** | 员工的专业技能证书 | "请帮我做XX"这句话 |
| **复杂度** | 复杂，包含多个维度 | 简单，通常是一段文字 |
| **复用性** | 高度可复用 | 通常一次性使用 |
| **可维护性** | 版本化管理 | 随用随写 |
| **效果** | 稳定、一致、可预测 | 效果随写法波动 |

### 具体对比

**Prompts（提示词）的典型形态：**
```
请帮我筛选这份简历，看看候选人是否适合Java工程师岗位。
```

这只是一个指令，AI 会按自己的理解去执行，结果不可控。

**Skills（能力模块）的典型形态：**
```
┌─────────────────────────────────────────┐
│           Java工程师筛选 Skill           │
├─────────────────────────────────────────┤
│  1. 筛选标准（硬性门槛 + 能力要求）        │
│  2. 评分规则（维度 + 权重 + 评分标准）     │
│  3. 评估流程（步骤 + 判断逻辑）            │
│  4. 输出规范（格式 + 字段 + 验证规则）     │
│  5. 质量保障（依据引用 + 核实机制）        │
└─────────────────────────────────────────┘
```

这是一套完整的能力定义，AI 会按照预设的标准和流程执行，结果稳定可控。

## 为什么 Skills 设计如此关键

### 1. Skills 决定筛选质量的上限

再好的 AI 模型，如果 Skills 设计不合理，也无法产出高质量的筛选结果。

**反例：Skills 设计不当**
```
硬性门槛：本科以上
评分维度：综合能力（100%）
```
这样的 Skills 太模糊，AI 无从判断，结果随机性大。

**正例：Skills 设计精良**
```
硬性门槛：
- 本科及以上（计算机相关专业优先）
- 3年以上 Java 开发经验
- 熟悉 Spring 框架

评分维度：
- 技术深度（30%）：JVM、多线程、设计模式
- 项目经验（25%）：高并发、分布式系统
- 工程能力（20%）：代码规范、测试习惯
- 学习能力（15%）：新技术追踪、持续学习
- AI协作能力（10%）：AI工具使用经验
```

### 2. Skills 必须与公司和岗位匹配

**同样是"Java工程师"，不同公司的 Skills 应该完全不同：**

| 公司类型 | Skills 重点 |
|---------|------------|
| 互联网大厂 | 高并发、分布式、系统设计 |
| 金融科技 | 安全合规、稳定性、事务处理 |
| 传统企业 | 业务理解、文档能力、沟通协作 |
| 创业公司 | 全栈能力、快速迭代、多面手 |
| AI 公司 | AI 集成、Prompt Engineering、Agent 开发 |

**直接套用通用模板会导致：**
- 筛选出的候选人与实际需求不匹配
- 错过真正适合的候选人
- 评估结果缺乏针对性

### 3. Skills 是企业招聘标准的数字化

一套精心设计的 Skills，实际上是企业以下内容的结晶：

- **企业文化**：我们看重什么类型的人？
- **战略方向**：未来需要什么能力的人才？
- **团队现状**：当前团队缺什么？需要互补什么？
- **行业特点**：我们行业有什么特殊要求？
- **岗位实际**：这个岗位日常做什么？需要什么技能？

**Skills 设计不是技术活，而是战略活。**

## Skills 的核心组成

本系统中，一个完整的 Skill 包含以下五大组成部分：

### 1. 筛选标准（评估"尺子"）

定义什么样的候选人符合要求。

```
┌─────────────────────────────────────────┐
│              筛选标准                    │
├─────────────────────────────────────────┤
│  硬性门槛：不符合直接淘汰                  │
│  - 学历要求                              │
│  - 专业要求                              │
│  - 工作年限                              │
│  - 必备技能                              │
│  - 必备证书                              │
├─────────────────────────────────────────┤
│  核心能力：重点评估的能力维度              │
│  - 专业能力                              │
│  - 经验匹配度                            │
│  - 软技能                               │
├─────────────────────────────────────────┤
│  加分项：符合优先安排                     │
│  - 行业背景                              │
│  - 特殊技能                              │
│  - 证书资质                              │
└─────────────────────────────────────────┘
```

### 2. 评分规则（打分逻辑）

定义如何量化评估候选人。

- **评分维度**：从哪些方面打分（通常 4-6 个维度）
- **权重分配**：各维度的相对重要性（加起来 = 100%）
- **评分标准**：1-5 分各代表什么含义
- **分档规则**：总分如何映射到 S/A/B/C 档位

### 3. 评估流程（执行步骤）

定义 AI 如何一步步完成评估。

1. 门槛检查 → 快速过滤不合格者
2. 维度评分 → 逐项量化评估
3. 亮点识别 → 发现候选人优势
4. 疑点标记 → 标记需核实的信息
5. 全网核实 → 搜索验证关键信息

### 4. 输出规范（结果格式）

定义评估结果的输出格式。

- **结构化格式**：JSON / Markdown
- **必填字段**：确保关键信息不缺失
- **依据引用**：每个评分必须有简历原文支撑
- **审计字段**：记录评估时间、模型版本等

### 5. 质量保障（约束机制）

确保评估结果的质量和可靠性。

- **依据引用**：不能凭空打分
- **一致性**：相同简历多次评估结果一致
- **可追溯**：每个结论都能找到依据
- **核实原则**：宁缺勿滥，不采用不确定信息

## 本系统中的 Skills 架构

### 目录结构

```
templates/Skills库/              # 原"提示词库"，现更名为 Skills 库
├── 通用/
│   └── 基础Skill_模板.md        # 创建新 Skill 的起点
├── HR部门/
│   ├── HR专员_Skill.md
│   └── HRBP_Skill.md
├── 技术部门/
│   ├── Java工程师_Skill.md
│   ├── 前端工程师_Skill.md
│   └── 产品经理_Skill.md
├── 财务部门/
│   └── 财务专员_Skill.md
└── 市场部门/
    └── 市场专员_Skill.md
```

### Skills vs Prompts 在本系统中的角色

| 组件 | 在本系统中 | 说明 |
|------|----------|------|
| Skills 定义 | `templates/Skills库/*.md` | 包含完整的能力定义 |
| Prompts 执行 | 发送给 Claude 的指令 | 激活 Skill 并传入简历 |
| 评估输出 | `workspace/02_筛选结果/*.json` | Skill 执行后的结果 |

### 使用流程

```
1. 选择/定制 Skill
   ↓
2. Skill 内容 + 简历 → 形成 Prompt
   ↓
3. 发送 Prompt 给 Claude
   ↓
4. Claude 按 Skill 定义执行评估
   ↓
5. 输出标准化评估报告
```
