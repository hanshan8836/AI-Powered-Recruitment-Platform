## 二、Step 1：收集需求

### 2.1 与用人部门沟通

需要确认以下信息：

| 信息项 | 说明 | 示例 |
|--------|------|------|
| 岗位名称 | 具体岗位名称 | Java后端工程师 |
| 招聘人数 | 本批次需要招聘的人数 | 2人 |
| 到岗时间 | 期望到岗日期 | 2026年3月1日前 |
| 硬性要求 | 必须满足的条件 | 本科、3年经验 |
| 核心能力 | 最看重的能力 | 技术深度、项目经验 |

## 三、Step 2：制定筛选标准

### 3.1 填写备案表

使用模板：`templates/备案文件/筛选标准备案表_模板.md`

**填写要点：**

#### 3.1.1 硬性门槛

- 必须是**可验证**的客观条件
- 每一项都要明确**是否必须**
- 不符合任何一项硬性门槛的简历将被**直接淘汰**

```
示例：
| 项目 | 要求 | 是否必须 |
|------|------|:--------:|
| 学历 | 本科及以上 | 是 |
| 专业 | 计算机相关 | 否（有经验可放宽） |
| 工作年限 | 3年及以上 | 是 |
```

#### 3.1.2 评分维度与权重

- 所有维度权重**加起来必须等于100%**
- 每个维度的**评分标准必须明确**
- 评分标准应该是**可量化、可评估**的

```
示例：
| 维度 | 权重 | 评分标准 |
|------|------|---------|
| 教育背景 | 10% | 5分=985/211+相关专业；4分=普本相关；3分=普本其他；2分=专科+经验；1分=不符 |
| 工作经验 | 25% | 5分=5年+大厂；4分=3-5年；3分=2-3年；2分=1-2年；1分=<1年 |
| 技术能力 | 30% | 5分=精通+原理；4分=熟练；3分=了解；2分=入门；1分=不足 |
| ... | ... | ... |
```

#### 3.1.3 分档标准

使用统一的分档标准：

| 档位 | 分数范围 | 处理建议 |
|:----:|:-------:|---------|
| S档 | 4.5-5.0 | 优秀，优先安排面试 |
| A档 | 3.5-4.4 | 良好，正常安排面试 |
| B档 | 2.5-3.4 | 一般，视情况安排 |
| C档 | 1.5-2.4 | 较弱，暂缓安排 |
| 淘汰 | <1.5或未过门槛 | 不安排面试 |

## 四、Step 3：选择/定制提示词

### 4.1 使用现有提示词

如果是常见岗位，可直接使用提示词库中的模板：

| 部门 | 岗位 | 提示词文件 |
|------|------|-----------|
| HR部门 | HR专员 | `templates/提示词库/HR部门/HR专员_提示词.md` |
| HR部门 | HRBP | `templates/提示词库/HR部门/HRBP_提示词.md` |
| 技术部门 | Java工程师 | `templates/提示词库/技术部门/Java工程师_提示词.md` |
| 技术部门 | 前端工程师 | `templates/提示词库/技术部门/前端工程师_提示词.md` |
| 技术部门 | 产品经理 | `templates/提示词库/技术部门/产品经理_提示词.md` |
| 财务部门 | 财务专员 | `templates/提示词库/财务部门/财务专员_提示词.md` |
| 市场部门 | 市场专员 | `templates/提示词库/市场部门/市场专员_提示词.md` |

### 4.2 定制新提示词

如果是特殊岗位，基于通用模板定制：

1. 复制 `templates/提示词库/通用/基础提示词_模板.md`
2. 修改所有 `[待填写]` 部分
3. 确保与备案表中的标准**完全一致**
4. 保存为新文件，命名格式：`[岗位名称]_提示词_v[版本号].md`

### 4.3 提示词检查清单

在提交审批前，检查提示词是否包含以下内容：

- [ ] 角色定义（明确告诉AI它是什么角色）
- [ ] 筛选标准（与备案表一致）
- [ ] 评分规则（权重、评分标准、分档）
- [ ] 评估任务（门槛检查、评分、核实等）
- [ ] 输出格式（JSON格式定义）
- [ ] 特别提醒（岗位特殊关注点）

## 五、Step 4：审批签字

### 5.1 审批流程

```
HR填写备案表 → 用人部门确认 → HR负责人审核 → 审批人签字
```

### 5.2 审批内容

审批人需要确认以下内容：

1. **筛选标准是否合理**：门槛是否过高/过低
2. **权重是否合理**：是否反映岗位真实需求
3. **提示词是否完整**：是否包含所有必要内容
4. **AI模型是否适合**：是否使用指定的模型

### 5.3 审批后的要求

一旦审批通过：

- **不得修改**任何内容（包括标准、权重、提示词）
- 如需修改，必须**重新备案、重新审批**
- 备案文件将在筛选结束后**对外公示**

## 七、常见问题

### Q1: 如果用人部门临时增加新的筛选条件怎么办？

**A**: 必须重新备案。备案文件一经审批，不可修改。

### Q2: 提示词可以在筛选过程中优化吗？

**A**: 不可以。提示词必须与备案文件一致，且在筛选过程中保持不变。

### Q3: 如果发现备案的标准不合理怎么办？

**A**: 有两个选择：
1. 停止当前筛选，重新备案，从头开始
2. 按当前标准完成筛选，在下一批次调整标准

### Q4: 备案文件保存多久？

**A**: 永久保存。所有备案文件、筛选记录都要归档，供事后审计。
