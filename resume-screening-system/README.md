## 系统概述

本系统基于 **Claude Code Agent** 本地化运行，为企业提供一套标准化的AI简历筛选流程。

### 为什么需要这套系统？

1. **公平公正**：所有筛选标准、Skills、评分权重必须事先备案，筛选过程中不可修改
2. **透明可查**：筛选结束后公示标准，候选人可查询个人评估结果
3. **全程留痕**：所有评估都有据可查，支持事后审计
4. **宁缺勿滥**：全网核实只采用100%确定的信息，不因搜不到就判定造假

### 适用场景

- 企业批量简历筛选
- 校园招聘简历初筛
- 社会招聘简历评估
- 内部竞聘材料评审

## Skills 框架

> **核心理念**：Skills（技能/能力模块）是本系统的灵魂。每个企业都应该根据自身特点设计专属的 Skills，而不是直接使用通用模板。

### Skills 和 Prompts 的区别

| 概念 | 本质 | 类比 |
|------|------|------|
| **Skills** | 封装好的能力模块 | 员工的专业技能证书 |
| **Prompts** | 单次执行的指令 | "请帮我做XX"这句话 |

**Prompts 是"指令"，Skills 是"能力"。**

一个完整的 Skill 定义包含：
- **筛选标准**：硬性门槛 + 核心能力要求 + 加分项
- **评分规则**：评分维度 + 权重分配 + 评分标准
- **评估流程**：门槛检查 → 维度评分 → 亮点识别 → 疑点标记 → 全网核实
- **输出规范**：JSON 格式 + 必填字段 + 依据引用
- **质量保障**：一致性保证 + 可追溯机制

### 为什么 Skills 设计如此重要？

**同样是"Java工程师"，不同公司的 Skills 应该完全不同：**

| 公司类型 | Skills 重点 |
|---------|------------|
| 互联网大厂 | 高并发、分布式、系统设计 |
| 金融科技 | 安全合规、稳定性、事务处理 |
| 传统企业 | 业务理解、文档能力、沟通协作 |
| AI 创业公司 | AI 集成、Prompt Engineering、快速学习 |

**直接套用通用模板的后果：**
- 筛选出的候选人与实际需求不匹配
- 错过真正适合的候选人
- 评估结果缺乏针对性

## 快速开始

### 前置要求

1. 已安装 [Claude Code CLI](https://docs.anthropic.com/claude-code)
2. 有效的 Claude API 访问权限
3. 本地运行环境（macOS / Linux / Windows WSL）

### 开始之前：理解 Skills

**在使用系统前，请务必阅读：**
1. [Skills 框架说明](docs/Skills框架说明.md) - 理解核心概念
2. [Skills 设计指南](docs/Skills设计指南.md) - 如何定制你的 Skills

### 5分钟快速体验

```bash
# 1. 进入系统目录
cd resume-screening-system

# 2. 将待筛选简历放入指定文件夹
cp /path/to/resumes/*.pdf workspace/01_待筛选简历/

# 3. 选择或定制 Skills（重要！）
# - 查看现有 Skills 模板：templates/Skills库/
# - 根据公司特点定制 Skills（参考 docs/Skills设计指南.md）

# 4. 复制并填写备案文件
cp templates/备案文件/筛选标准备案表_模板.md workspace/我的备案.md
# 编辑 workspace/我的备案.md，填写岗位要求

# 5. 启动Claude Code，执行筛选
claude

# 6. 在Claude中发送筛选指令（参考 docs/第二阶段_执行指南.md）
```

## 使用指南

### 1. 如何选择/设计 Skills？

> **警告**：Skills 设计是整个系统成功的关键。请务必根据公司特点定制，不要直接使用通用模板。

**如果是常见岗位：** 参考 `templates/Skills库/` 中对应岗位的 Skills，然后根据公司特点调整权重和标准

**如果是特殊岗位：** 基于 `templates/Skills库/通用/基础Skill_模板.md` 从头设计

**Skills 设计原则：**
- 权重分配反映公司价值观（核心能力权重最高）
- 评分标准必须具体、可衡量
- 必须明确硬性门槛（不符合直接淘汰）
- 必须明确输出格式（JSON 或 Markdown）

**详细指南：** [docs/Skills设计指南.md](docs/Skills设计指南.md)

### 2. 如何进行全网核实？

**核实原则：宁缺勿滥**

| 搜索结果 | 判定 | 标记 |
|---------|------|------|
| 搜到官方来源，信息完全匹配 | 采用 | 已核实 |
| 搜到信息但不完全确定 | 不采用 | 无法确认 |
| 完全搜不到 | 不采用 | 未找到公开信息 |

**禁止事项：**
- 禁止因为搜不到就判定"造假"
- 禁止采用不确定的信息
- 禁止用模糊结果给候选人扣分

### 3. 如何处理申诉？

1. 候选人提交申诉
2. HR调出评估报告和备案文件
3. 核对评分依据是否正确
4. 如有错误，修正并记录
5. 5个工作日内反馈结果

## 常见问题

### Q: 筛选过程中可以修改 Skills 吗？

**A: 不可以。** 备案文件一经审批，在本批次筛选结束前不得修改。如需调整，必须：
1. 停止当前筛选
2. 重新设计 Skills
3. 重新提交备案
4. 重新审批
5. 从头开始筛选

### Q: Skills 和 Prompts 到底有什么区别？

**A:** Skills 是"能力模块"，Prompts 是"指令"。详见 [Skills 框架说明](docs/Skills框架说明.md)。

简单来说：
- Skills = 员工的专业能力证书
- Prompts = "请帮我做XX"这句话

### Q: 全网核实搜不到信息怎么办？

**A: 标记为"未找到公开信息"，不作为负面依据。** 很多小公司或普通员工没有网络信息，搜不到不等于造假。建议在后续面试或背调环节确认。

### Q: 如何保证AI评估的一致性？

**A: 通过以下措施保证：**
1. 使用相同的 Skills（备案锁定）
2. 使用相同的模型版本（备案记录）
3. 所有评分必须引用简历原文作为依据

### Q: 候选人可以查询自己的评估结果吗？

**A: 可以。** 筛选结束后，候选人可以申请查询个人评估结果，包括：
- 各维度得分及依据
- 档位判定
- 未通过原因（如适用）
